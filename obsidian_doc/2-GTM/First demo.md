# Demo First

**Rule: don't plan, don't optimize, don't document. Demo → learn → build what's missing.**

---

## Priority order

1. **Write the demo script** (1 page max — the story you walk the coach through)
2. **Make the demo work** end-to-end
3. **Show the coach**
4. **Write down what he said** — that becomes the real roadmap
5. Tech decisions come after validation

## The demo script (draft)

Two stories to show — scheduling automation AND discovery/leads:

**Story 1: Scheduling automation**
1. Coach creates a group lesson (e.g. Tuesday 18:00, 4 spots, recurring weekly)
2. Coach sends invite link to his players
3. Players sign up and confirm attendance — one tap
4. Someone cancels → waitlist person gets auto-notified → spot fills without coach doing anything
5. Coach opens dashboard → "all spots filled, nothing to do"

**Story 2: Discovery & leads**
1. Coach has a public profile with bio, sport, location, reviews
2. Athlete searches "tennis coach Warsaw" → finds the coach
3. Athlete sees ratings, reviews, available slots → requests to join or book
4. Coach gets a new lead without doing anything

**If the demo can show both stories, you're proving the full value. If it can only do one, start with scheduling — but don't forget discovery is half the pitch.**

## After the demo — capture these

- What excited the coach
- What confused him
- What he said he still needs (that Sessio doesn't do yet)
- Would he actually use this tomorrow — yes or no

## What NOT to do right now

- Don't pick a new hosting provider
- Don't refactor the Lovable code
- Don't write more strategy docs
- Don't build payments
- Don't build anything the demo doesn't need
